# 20｜时空漫游者：双样板与创作优先的开发范围（V2）

2026-10-13。对应代码分支 `feature/configurable-observation-hints`，设计基线 `f1e2ca5`。本文是对原《18-Builder-Agent-设计.md》《19-Builder-Agent-真实依赖与实施手册》的**范围调整**，不取代仓库现有数据安全和人工审核机制。

## 1. 产品目标与边界

真正要证明的不是“资料核验多准确、解谜多复杂”，而是：**一句创作意图可以被制作成可演绎、可编辑、可发布的沉浸式旅行故事；同一引擎能承载显著不同的故事风格。**

验收必须包含两份互不相同的、真正通过现有播放器运行的景点体验包：

- A：豫园《一封穿越四百年的家书》，历史人文、暖金诗意、书信媒介；复用现有豫园素材和地点。
- B：上海天文馆《来自宇宙尽头的讯息》，未来科幻、深蓝冷白、无线讯号媒介；基于“家园”“宇宙”“征程”等正式展区，剧情明确为艺术创作。

两者采用同一 `ExperienceDefinitionV1` / `storyEngine.ts`。不要为天文馆重新开发一套播放器。演示仅使用手动章节切换或已有模拟到达，**不建设馆内定位系统，也不承诺已实地验证路线**。

## 2. 两份体验的导演脚本骨架

### A：豫园

- 序幕：园门，得到一封迟到了数百年的家书；画面为纸墨、树影、水面。
- 第一幕：三穗堂，提出“建园究竟是为了什么”的情感线索。
- 第二幕：大假山，展开一段造园者的回忆；出现轻量选择“自然”或“匠心”。
- 分支：仅在叙事视角上分开，不要求路线分开；使用 `setVar` / `goTo`。
- 终幕：玉玲珑，回答悬念，生成个人旅途信笺。

### B：上海天文馆

- 序幕：用户收到一段无法解释的未来讯号；画面为信号噪点、星图。
- 第一幕：“家园”，从地球的独特性建立情感锚点。
- 第二幕：“宇宙”，利用深空尺度和时间变换扩大悬念。
- 互动：选择追寻讯号的“起点”或“终点”，产生两种旁白视角。
- 终幕：“征程”，发现讯号的意义来自人类不断探索的愿望；生成个人“航行记录”。

场景名对应官方展区，但人物、未来讯号与故事反转均为原创虚构；不需要做大量事实考据。两个样板演示路径各约 2–3 分钟，推荐每个 4–6 个场景、一个选择分支、一处轻操作即可。

## 3. 展示主题适配：首要工程任务

当前 `ExperiencePlayer.tsx` 的开场和终幕存在豫园/家书专属文案，`experience.css` 采用单一古风主题，不能只换 JSON。

建议在 `PublishedAttraction` 增加可选 `presentation`，不修改 `ExperienceDefinitionV1` 的故事动作与编排结构：

```ts
type ExperiencePresentation = {
  preset: 'heritage' | 'cosmos'
  motif: 'letter' | 'transmission'
  locationMode: 'outdoor' | 'indoor'
  openingTitle: string
  openingText: string
  labels: { start: string; next: string; finish: string; journal: string; stage: string }
}
```

发布与编辑侧的 `DraftAttraction`、`publishedToDraft`、`toPublishedPackage` 需要透传这个字段；对可选字段做严格枚举校验，老包默认 `heritage`。主题换肤放在 CSS 变量中，**不要求一个 CSS 类对应一个景点**；未来引入第三种主题仅需新增预设。

- `heritage`：古铜金、深墨绿、宋体、水墨渐变、书信卡片；结尾叫“旅行信笺”。
- `cosmos`：深蓝黑、冷白蓝、现代无衬线、星云粒子/扫描线、讯号卡片；结尾叫“航行记录”。
- `locationMode=indoor`：地点标签视为展区，章节通过“进入展区”手动触发。可以使用场馆级坐标作为包结构兼容字段，但**不展示馆内精确路线、不声称能够自动判断展区位置**。

## 4. Builder Agent 的真实最短生产链

`CreativeBrief`（景点名、用户受众、主题、时长、风格倾向）
→ `LocationNotes`（现有景区包或 2–4 页公开资料摘要）
→ `StoryConcept[]`（模型提出两个有区别的故事命题，含人物/欲望/悬念/结局）
→ `SelectedConcept`（自动选高分或人工一键选）
→ `BeatSheet`（4–6 幕，每幕绑定真实展区名或景点名）
→ `ExperienceDefinitionV1`（使用白名单动作生成可运行故事）
→ `Presentation`（主题、开场媒介、按钮文案）
→ `MediaRequests`（每幕插画/配音）
→ `AgentDraft`（浏览器导入独立待审草稿）
→ 原编辑器与发布链路。

**新加的价值关键是两个故事概念和分幕节拍，而不是事实级 Critic。** 一个 `NarrativeCritic` 仅返回四项意见：开头是否吸引、章节之间是否推进故事、地点是否影响剧情、结尾是否回收悬念。用于定向修改，不把主观评分做硬发布门槛。

必须区分 `ExistingBuilder` 的旧白名单与新 Agent 导入路径：旧 `assertBuilderCandidate` 不允许新增资料/图片，新 Agent 需 `assertAgentCandidate` 加受控新增资产。`materializeMedia` 还需增加故事 `blocks[].assetRef` 的收集、保存、引用替换和离线回放验证。浏览器 `localStorage` 由前端接收服务端候选并调用 `saveDraft` 写入，服务器不能直接替用户写浏览器草稿。

## 5. 外部数据与服务依赖：减负后的选择

- **地点与官方展区**：豫园已有仓库包；上海天文馆资料使用上海市政府和馆方的公开介绍；取“家园”“宇宙”“征程”三级展区名就足够编故事。若需要场馆坐标，统一通过高德检索场馆级位置，非必需室内路径。
- **网页搜索**：首选 Tavily，按“展区”“有趣知识”“建筑特色”“视觉元素”搜 2–4 个结果即可。只保存原文链接与少量摘要，不建设 claim-level 证据关系网络。若现场无 Web Search key，可先以小型预取资料包作为输入，仍须让后续创作调用真实模型。
- **天文画面**：优先 NASA Image and Video Library API (`https://images-api.nasa.gov/search?q=nebula&media_type=image`) 获取真实天体图作为素材候选，再用 Seedream 生成独特的科幻通讯/UI气氛和人物画面。NASA 图像受其媒体使用规范限制：需署明来源，区分第三方版权，尤其不能用 NASA 标识造成官方背书误解。原有天文馆内部实景图片需要授权或使用团队自有照片。
- **生图**：首选已经讨论的 Seedream（需 `ARK_API_KEY`、模型访问权、预算），直接产出 9:16 主视觉。生成图 URL 及时下载至受控素材目录，不写临时 URL 进发布包。两样板各 2–3 张重点画面，其余用已有或合法来源图片。
- **旁白**：现有浏览器朗读保证基本运行；优先使用支持导出音频的中文 TTS 制作预生成 MP3（每个样板约 3–5 段），播放器统一使用 `audio` 块。不要在游客端每一章动态合成。

## 6. 任务分工与依赖（2–4 人可并行）

| 任务 | 优先级 | 产出 / 验收 |
|---|---|---|
| V2-01 玩家端主题抽象 | P0 | 改写硬编码开场/终幕、两个展示预设；旧豫园不回归 |
| V2-02 天文馆基础包 | P0 | 以“家园、宇宙、征程”为地点条目，能够独立进入故事播放器；不模拟 GPS |
| V2-03 天文馆原创剧情 | P0 | 4–6 幕、一个两分支选择、完整结局、手动确认下一幕 |
| V2-04 双样板美术资产 | P0 | 每个主题至少两张高质量画面，视觉风格显著不同 |
| V2-05 新 Agent 候选导入 | P0 | 新增资产和来源可落草稿，原景点不变、发布后图片不丢 |
| V2-06 StoryConcept + BeatSheet | P0 | 同一套模型链对两个景点输出不同故事理念、章节和风格 |
| V2-07 实际模型贯通编译 | P0 | 非模板文本，生成 JSON 通过 `assertExperience` 并进入播放器 |
| V2-08 TTS、音效 | P1 | 两包主要章节有预生成旁白和音效；失效可阅读文字 |

建议 4–5 个开发日：第 1 日先完成主题抽象+天文馆内容包结构；第 2 日跑通第二个独立体验；第 3 日打通真实模型概念→节拍→编译；第 4 日素材生成和媒体发布闭环；第 5 日做两套样板的端到端彩排、修图和讲稿。可按团队人数并行，时间只是规划目标，并非已验证工时。

## 7. 答辩演示结构（总计约 5 分钟）

1. 0:00–0:35：产品主张“让世界成为你的故事”，展示双主题封面。
2. 0:35–1:45：豫园家书故事关键片段、一次轻选择、情感结尾。
3. 1:45–2:55：无须切换播放器代码，直接进入天文馆深空讯号体验，展示完全不同的图像、声音和开场形式。
4. 2:55–4:15：进入 Builder Studio，选择天文馆或另一景点，输入主题，展示两种故事命题、生成分幕与主题建议、内容进入可视化编辑器。
5. 4:15–5:00：讲清架构——“同一契约 + 同一运行时 + 多主题渲染 + Builder 生产线”；总结可规模化的文化、科普、自然、城市等旅行体验，而非宣称已经覆盖所有领域。

**最重要验收**：两包独立可打开、双主题差异明显、分支可完成、至少一段真实模型生成并能被编译采纳、关键新媒体发布后无断链、无真实 Provider key 时既有成品仍可运行。不要把复杂后台流程替代为样板质量。
