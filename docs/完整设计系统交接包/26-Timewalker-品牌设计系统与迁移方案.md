## 0. 一句话设计主张

**Timewalker · Temporal Editorial：像翻开一本关于世界的故事集，同时具有现代数字产品的操作精度。**

以用户已选定的「时空漫游者」星轨中文字标为母体，继承墨黑字形、金色轨迹、少量天体节点、方向感和大片留白。整体氛围是「文化编辑设计 × 现代探索仪器」，拒绝流行旅游 App 的蓝白模板感，也拒绝把所有故事强行套进古风皮肤。

设计系统分为三层：

1. **Brand Shell 品牌层**：首页、顶栏、页脚、导航、表单、按钮、提示、地图的工具性控件，统一纸白/墨黑/轨金、细边界、高级排版。这是不可随故事变化的身份锚点。
2. **Experience Skin 叙事层**：每个故事可以有夜色、古籍、星空等独特世界观。故事配色、转场、图片和叙述布局独立，框架交互保持一致，不自动继承品牌金色到全屏。
3. **Scene Art 内容层**：红山动物园悬疑、豫园古典、乐山旅行等素材内容，不由设计系统强行再着色。系统对它们负责裁切、文字对比、渐变遮罩与预加载。

**禁止：** 看到品牌有金色，就把所有主按钮改为金色；看到 LOGO 有轨道，就给每张卡加金色轨道；为了“高级”让重要操作失去对比和焦点。品牌越克制，作品越有空间。

## 2. 品牌资产规范

**字标为主，轨道为辅。** 在页面顶栏使用真实字标；它是品牌专用、完整可读的艺术字体，不是网站所有标题的通用字体。页面大标题选用高品质中文宋体/明朝体回退（如 Noto Serif SC、Songti SC）；正文和表单保持高可读性的黑体（Noto Sans SC、PingFang SC 等），英文字体可使用系统 serif/sans 组合。

| 场景 | 品牌表示 | 规则 |
|---|---|---|
| Web 页眉 | 黑字金轨完整字标 | 白/纸白底，周围至少保持一个字标内「时」字宽度的清晰空间 |
| 内容页标题 | 编辑式宋体标题 | 不重复 LOGO 的异形笔画，不加入模拟艺术字压缩 |
| 地图浮层 | 小型 TIMEWALKER / 模式名 | 主要导航文本突出景点与章节，品牌不抢地图层级 |
| 故事开场 | 低密度小品牌标识 + 强画面标题 | 可配一条细轨道线或微型四角星，**只能有一个主视觉意象** |
| 页脚 | 细分隔线 + TIMEWALKER 文字 / 小字标 | 禁用临时加粗的超大「时空漫游者」与 LOGO 竞争 |
| Favicon / App icon | 独立图形化标识 | 字标不要缩成 32px；图标需单独设计，如轨道/指针组合 |

**资产说明**：现有 `public/timewalker-logo.png` 已被 `SiteHeader` 使用，工程优先复用它。交接包里的裁剪版仅用于设计预览。若最终投产，需要设计师从 LOGO 源文件导出透明底 SVG/PNG，并人工校验中文字形；不要通过程序自动描摹作为正式矢量字标。字体文件不随本交接包提供。

## 3. 颜色架构：先语义，后主题

### 3.1 品牌原色（Primitive）

| 色彩 | 建议值 | 用途 |
|---|---|---|
| Star Ink / 星墨黑 | `#202527` | 主按钮、标题、深色交互锚点 |
| Orbit Gold / 轨道金 | `#B58B59` | 细线、星轨、图形节点、少量装饰（**浅底上不用于正文**） |
| Gold Text / 深轨金 | `#81603B` | 浅底可读的金色文字、部分状态标识 |
| Paper / 纸白 | `#F7F5EF` | 品牌页面底色 |
| Canvas / 空白 | `#FFFFFF` | 主内容表面、地图控件白底 |
| Stone / 石雾灰 | `#DFD9CA` | 边框、辅助纹理 |
| Pine / 苔石绿 | `#50635D` | 路线、环境探索相关辅助色，非默认操作主色 |
| Quiet Ink / 辅助字 | `#5E6766` | 描述、次级标签、帮助文案 |

WCAG 对比说明：`#B58B59` 在 `#F7F5EF` 上约 2.83:1，**不足以作为小号正文**；`#81603B` 在纸白上约 5.25:1，可作为文字配色。`#202527` 在纸白上约 14:1，适合主要阅读与按钮。

### 3.2 语义层（Semantic）

不允许页面直接理解 `gold`=主操作，应该映射为：

- `action.primary`: 深色实心墨黑 + 纸白文字。全站只有一个最显著操作层级。故事暗色环境内由 `on-dark` 反转或主题自身 Accent。
- `action.secondary`: 透明或白底 + 淡描边 + 墨黑正文。用于返回、切换、恢复等。
- `action.quiet`: 文字/图标操作。用于查看来源、展开、调整等低优先级操作。
- `feedback.focus`: 对比足够的金色/深金外描边；不依赖底色变化表达焦点。
- `feedback.info`: 产品信息/解释；和主 CTA 有区别。蓝色可以用于具体地点服务状态，但不是通用操作色。
- `feedback.error/success/warning`: 独立状态色；错误不可使用品牌金替代。
- `state.selected`: 选中态必须同时具备边框、形状/勾选/文字或图标，不能单靠色差区分。
- `surface.overlay`: 针对地图设计的半透明纸白浮层，而不是所有普通卡都使用毛玻璃。

**深色电影场景例外**：故事内允许冷光蓝、暖琥珀或暗红作为“主题强调色”，但它们被定义在 `.experience-theme` 作用域内，不能写到全局 `:root`。

## 4. 排版、几何、阴影、动效

**编辑式排版**：一级叙事标题宋体 36–52px（移动端 28–36）；页面功能标题 24–30px；面板标题 18–20px；正文 14–16px；辅助与时间刻度 12–13px，不能以 10px 代替可读正文。故事旁白行高 1.8–1.95，工具栏表单 1.45–1.6。英文字母 TIMEWALKER 使用大写、字距 0.18–0.3em，但中文正文不整体扩大字距。

**几何不是越圆越好**：主卡片圆角 16px、地图浮层 14px、输入框 10px、小按钮 10px；只有胶囊标签/局部导航使用 999px，电影画框可按剧目特殊处理。默认弱边界 `1px solid`，仅用于地图浮层和模态弹窗的中/强阴影；常规白卡**不需要每张都 shadow-md**。

**间距网格**：基本间距 4px，常见 8 / 12 / 16 / 24 / 32 / 48 / 64px。首页容器 1200px（旧 `max-w-5xl` 可按布局分阶段升级），正文阅读列最大 700–760px，发布工作台按信息密度单独设定。

**运动语义**：

| 动作 | 时间 | 曲线/含义 |
|---|---|---|
| 按钮与选择反馈 | 120–180ms | 即时响应，不能拖慢操作 |
| 浮层/章节进入 | 240–340ms | 轻微淡入 + 6–10px 位移 |
| 首图渐显/故事舞台 | 600–850ms | 情绪进入，支持懒加载和简化动效 |
| 路线轨道推进 | 350–500ms | 沿路径逐步连接节点，不要全局转圈 |

`prefers-reduced-motion: reduce` 必须关闭位移动画、循环脉冲、炫光，仅保留必要的信息切换。不能用纯动画提示事件成功。

## 5. 组件目录（第一版最多 8 个）

**P0 基础组件**：`Button`/`ActionLink`（primary/secondary/quiet/danger）、`Surface`（standard/raised/glass）、`TextField` / `TextArea`、`Badge`（mode/status 分离）、`Toast`（success/error/info/progress）、`Dialog`（含焦点管理）、`SectionHeader`、`StoryChoice`。

不要初期引进完整外部设计系统再包二次封装，也不必构建 Figma Tokens 服务器。先用 TypeScript + Tailwind CSS 4 + CSS Variables 实现可被前端真正复用的八个高频组件。

**Button 状态矩阵**（需作为 Storybook/演示页基础）：默认、悬停、聚焦、按下、禁用、加载、危险。主操作暗色实心；次操作描边；纯文字用于辅助。最小触摸目标 44px，不能在仅有背景变化时去掉默认 outline。用于 `<Link>` 的操作要使用链接语义，不把链接伪装成 button 导致键盘行为不一致。

**地图浮层规范**：`Surface variant="glass"` 固定一个透明度区间、模糊半径、阴影和边框，不在 `TourProgressBar`、`AskAiPanel`、故事信息卡分别写一套。故事地图的焦点层应通过对比与遮罩突出**当前章节**，不是通过 5 个同时漂浮的卡片抢注意力。普通后台卡片禁止使用高模糊，减少视觉噪音和性能负担。

**Toast**：在应用 Shell 中集中挂载通知区域，业务只调用 `notify({kind,message})`；原有 `GenProgressToast` 可以调用统一视觉结构但继续显示 progress 子内容，不必现在改掉 AI 业务逻辑。警告、错误不能只靠颜色表示。实时进度需要 `aria-live` 策略，避免每一个 token 都播报。

## 6. 分页面规范（对应现有路由，不假设不存在的 StoryEngine）

### 6.1 首页 `/` — 探索一本世界故事集

从“选择景点开始漫游”的普通列表页面，升级为“编辑精选封面 + 目的地故事目录”：页眉小字标，首屏独立的大标题「每一个地方，都有另一种抵达方式」，下方以小字号英文 `CURATED EXPERIENCES / TIMEWALKER` 提示策展语境；主视觉保留现有动物园大图，但增加故事所属类型、章节数、预计时间和清晰的开始按钮。底部景点卡以画面为主，留白、字体层级一致；**故事与打卡是内容类型，而非黑白标签随意堆叠**。

保留现有轮播与目录加载逻辑，不首先重构数据获取。视觉优先改 Header + Hero + 卡片的排版，选中态、按钮形状、链接下划线受 Token 控制。故事悬疑不宜被总品牌的奶油金照亮：内容卡图像依旧可以保持原始深蓝黑调。

### 6.2 故事地图 `/tour/:id`（mode = story） — 从操作地图转为故事舞台

现在的内容结构是地图 + 右上讲述卡 + 左下选项 + 顶部状态 + 居中模态。保留业务状态与事件，视觉改为：

- **开场**：覆盖地图的深色“序章卡”优先展示人物/场景封面、大标题、背景声与清晰开始动作；地图在后层弱化。当前纯白标准模态过于管理化。
- **游览中**：右侧叙事浮层作为主人公，图片高度可控、章节号和「夜色中的线索」字幕提供文稿节拍；地图基础导航仍清楚，地图不是故事主视觉。
- **选择发生时**：选项在左下／移动端下方形成“一次有意义的故事决策”，选中态采用细金边、浅金背景与明确的勾选/箭头，去除系统蓝色矩形按钮。
- **结尾**：用电影海报式 End Card 回收故事标题、走过的路线、最后选择和一句结语。操作仍含重新开始/自由漫游，不把完整剧情结果变成 Excel 汇总。
- **地图**：视觉叠层建议沿用 AMap 可读默认样式。抽象金色路线用于“当前路径与走过的章节”，不能代替真实地图路线，路线与点位颜色需要易于辨识。

### 6.3 打卡地图 `/tour/:id`（mode = checkin） — 从地图操作转为漫游仪表盘

同样的地图底座，但弱化电影叙述，突出今日路线、待访问地点与进度。可使用 `01 / 05` 的编号、轨道刻度、节点完成状态和印章微动效。和 Story 共享地图工具浮层及按钮，但不共享开场大段悬疑旁白。

### 6.4 编辑/发布 `/publish`、`/publish/:id`、`/publish/:id/...` — 创作者的编辑工作台

与游客端保持同一品牌 Shell，但更加工具性：纸白与低对比边框、明确的工作区边界、紧凑表单、固定顶部操作与保存反馈；可以用一条细金色章节线表达当前编辑阶段。禁用每个板块另造渐变和玻璃。

优先统一高频输入框、按钮、面板、Toast、确认对话框；不要同时重做所有复杂编排。创作区域可采用大字号宋体「故事结构」等大区标题，字段名仍是黑体，避免整页宋体降低编辑效率。

## 7. 技术实施方案

### 7.1 目录（新增，现有组件不移动）

```text
src/
  styles/
    timewalker.tokens.css       # 品牌基础色、语义色、栅格、字阶、半径、动效
    timewalker.components.css   # 原子组件样式与交互状态
  components/
    ui/
      Button.tsx               # Button + ActionLink；先从最高频操作接入
      Surface.tsx              # 普通卡 / Raised / Glass
      ...                      # 按真实复用量逐个迁移
  index.css                    # 导入 Tailwind 4 和设计系统 CSS，保留现有工具样式
  components/SiteHeader.tsx    # 接新 BrandButton 和文案
  pages/HomePage.tsx           # 首页视觉重构
  pages/StoryTourPage.tsx      # 叙事壳重构，逻辑不动
  pages/TourPage.tsx           # 地图浮层渐进迁移
  pages/content/*.tsx          # 编辑页输入/按钮/卡片
```

Tailwind 4 使用 `@theme inline` 将 CSS 自定义属性绑定到工具类，例如 `bg-brand-canvas`、`text-brand-ink`；同时保留语义化的 `var(--tw-color-action)`，以方便旧组件逐步迁移。**不要在一次 PR 中全局替换所有十六进制颜色**，尤其不能替换供应商地图颜色、照片遮罩与错误/警告色。

建议为沉浸主题使用 `[data-experience-skin="noir"]` 的变量作用域，以便故事世界观在暗色舞台切换，但保持顶栏/后台不被改色。现阶段只需定义 `noir`（红山动物园故事样例）、`heritage`（将来其他传统题材）和 `cosmos`（扩展样例）三套示例主题，**不是声称这些主题已在 fix/draft 功能中实现**。

### 7.2 渐进迁移 PR

| DS-02 | SiteHeader、SiteFooter、ModeTag、HomePage | 首页从模板卡片升级为 Timewalker 策展视觉 | 低-中 |

| DS-04 | TourPage、TourProgressBar、AskAiPanel | 地图工具浮层、路径选中与地图信息统一 | 中；需要屏幕尺寸回归 |
| DS-05 | Publish* + Content* + Toast | 编辑后台同一表单和通知系统 | 中；不能破坏表单提交、导出、预览 |
| DS-06 | 视觉回归、响应式与动作减弱 | 375/768/1440px 视觉检查、键盘 Tab、旧模式功能回归 | 低 |

**推荐优先顺序 DS-01→DS-02→DS-03**。对评委最直观的是：首页进入同一个品牌世界观、打开动物园悬疑第一幕并做一次选项、进入结局，然后回到编辑后台看到一致的品牌。最先把 StoryTour 改得像故事，比把管理后台每个 8px 圆角改成 10px 更有价值。

### 7.3 最小验收门槛

1. 在同一浏览器访问首页、红山故事地图、豫园打卡、内容编辑/发布，字标、行动按钮与辅助字阶均有统一规则，不出现蓝色主操作与黑色主操作同时竞争。
2. 红山故事**视觉氛围**明显更强，但文字/地图、选择与结局仍完整；所有原有按钮事件、进度恢复、AI 提示和导出逻辑不改变。
3. 在 375px 手机宽度，地图/故事主任务不被浮层完全覆盖，操作可达；在 1280–1440px 桌面宽度留白不显空；键盘 Tab 可观察焦点。
4. 白底正文、金色小字等达到 WCAG AA 正文对比要求；Orbit Gold 仅用于细纹饰，Gold Text 用于浅底有意义文字；主题深背景另行测量。
5. 不再新增页面级十六进制主按钮样式；允许短暂保留 legacy 原代码，但新组件必须使用语义令牌。
6. 运行 `npm run lint`、`npm run build`；关键路由人工回归操作。由于现有 `package.json` 没有 `npm test`，不要写一个实际上不存在的测试命令作为验收。

## 8. 建议团队确立的设计评审标准

每次 UI PR 必须回答：它属于品牌壳还是故事皮肤？有没有复用令牌/组件？大标题和正文哪个承载品牌风格？交互状态是否被用户看见？移动端是否有主任务？动效是否尊重降低运动选项？与现有截图相比，品牌和故事哪个变得更加突出？

**最终成功标志**不只是“所有页面颜色一样”，而是：打开首页无需解释就知道是 Timewalker；进入红山动物园又明显感觉自己到了另一个夜色世界；回到创作后台，仍能确认在同一款产品里创作这一切。
