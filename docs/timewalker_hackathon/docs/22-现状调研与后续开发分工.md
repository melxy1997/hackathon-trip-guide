## 1. 当前目标与执行优先级

产品：**时空漫游者 · 让世界成为你的故事**。技术表达：**Trip Experience Engine**。游客先体验沉浸故事、轻选择、观察和个人记录；创作者再展示从意图到可执行故事的生产能力。

**本轮唯一产品目标：快速可用、有演示效果。** 用户已明确：素材作者、原图链接、许可复核不属于本次黑客松开发目标，不进入任务排期、完成标准或发布阻塞条件。不要再把这些事项分配给成员。现有素材可继续用于样板迭代；旧资产清单中的 pending 是历史记录，不是本轮待办。

优先让观众看懂、玩起来、看到选择反馈，并让一次真实模型创作进入同一个播放器。结构校验、独立草稿和错误降级继续保留，因为它们直接防止演示中断或覆盖已有成果。沿用现有审核按钮即可，不建设新的审核后台。

本文是本轮分工入口；与早期方案的任务优先级冲突时，以本文为准。底层架构和数据契约继续参考 20、21 及实际代码。下文“建议接口/目录”均为待实现方案，不代表已经存在。

## 4. 下一阶段最短闭环

```text
已有景点/展区资料 + 创作意图
  → 模型给出两个不同故事概念
  → 用户选一个
  → 模型生成 4–6 幕节拍
  → 编译为 ExperienceDefinitionV1 + Presentation
  → 独立待审草稿
  → 现有编辑器 → 预览 → 发布
```

先复用现有地点、资料摘要和静态图片。**搜索、新生图、TTS 不必全部就位才开始跑通主线。** 不接复杂证据库，不强求每幕独立插画，不建设八类 Critic 或精细路线。

### 4.1 第一步：共享契约与独立候选导入（P0）

建议新增 `src/experience/agent/`，承载前后端共享类型及纯校验逻辑；不要把服务器密钥/文件读写导入浏览器。

| 契约 | 最少内容 |
|---|---|
| `CreativeBrief` | 景点 ID、主题、受众、目标时长、风格；复用两份已有 brief |
| `LocationNotes` | 基础包版本/指纹、已知地点 ID/名称、简短资料、可用媒体与来源引用 |
| `StoryConcept` | ID、标题、一句话命题、主角/欲望、悬念、地点如何参与、结尾回收 |
| `BeatSheet` | 概念 ID、4–6 个叙事节拍、地点绑定、分支与合流、观察任务、结局 |
| `AgentCandidate` | 基础包标识与版本、所选概念、节拍、experience、presentation、资源清单、诊断 |

节拍数量指玩家经历的章节；两个互斥分支可对应更多场景记录，不要为凑数组长度破坏分支。

必须单独实现 `assertAgentCandidate`、`createAgentDraft`，保留旧 `assertBuilderCandidate`。新候选允许受控新增素材/资料，但地点必须能映射到已知节点，媒体必须可解析；最终运行包仍过现有 schema 校验。

验收：合法候选可进入原编辑器；原包和已有草稿不变；导入是新的草稿 ID、待审状态；未知地点/媒体、非法动作、失效基础包版本给出可理解错误；导出后图片不丢。此阶段 fixture 仅验证契约，不算真实模型贯通。

### 4.2 第二步：真实概念→节拍→编译（P0）

在 `server/` 增加独立创作服务，复用现有 DeepSeek 网关的服务端调用能力，使用 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。不要新增无人读取的配置变量或另起一套浏览器直连模型。

建议分成概念、节拍、编译三个阶段，分别保存结构化产物。接口可先采用 `POST /api/agent/concepts`、`POST /api/agent/compile`：前者返回两个概念，后者接收选择并产出节拍和候选。最终路径由负责人与前端先确认，避免两边各自命名。

实现顺序：

1. 以已有资料包生成两个有实质区别的概念，区别应体现在悬念、地点作用和结尾，而非仅标题换词。
2. 选定概念后生成节拍；地点用现有 ID 映射，媒体先使用现有图片。
3. 编译为白名单动作的 V1 结构，校验并返回可定位诊断。允许一次有上限的定向修复，不无限重试。
4. 接独立候选导入；分别生成豫园、天文馆产物，在现有播放器完成分支。
5. 有余力再加一个 `NarrativeCritic`，仅返回开头吸引力、章节推进、地点作用、结尾回收四项简短建议，不设置主观分数硬门槛。

首版可用分阶段 HTTP 请求；出现长耗时步骤时再加轻量 Job：ID、阶段、状态、错误、产物、取消、超时、有限重试。需要脱离请求继续执行时使用独立生命周期与简单本地持久化，不照搬旧网关“连接断开即取消”的全部行为。**不要先花整轮开发搭复杂任务调度系统。**

验收：至少一条真实模型链完整生成并采用，最终目标是两景点都跑通；保留请求 ID、模型名、阶段产物和耗时作为演示依据，不存密钥。模型失败不清空上一份成功候选，模板备用入口仍可使用。

### 4.3 第三步：最小 Creative Studio（P0，核心链就绪后）

复用首页 Builder 入口和现有编辑器，新增独立组件即可，不重写首页/发布后台。

- 输入：景点、主题、受众、时长；可一键填入豫园/天文馆演示主题。
- 概念：两张卡片展示命题、悬念、地点作用、结局方向；支持选中继续。
- 节拍：按章节展示地点与剧情，标出选择、观察及合流；不让用户先读 JSON。
- 阶段：显示当前正在创意、分幕或编译，完成后可查看产物；不使用虚假精确百分比。
- 操作：继续、重试当前阶段、取消、采用并编辑；失败保留输入、已选概念与已有候选。
- 采纳：进入现有编辑器，保持独立待审；预览成功后沿用现有发布操作。

验收：从输入到预览有一条清晰路径；生成中不会重复提交；取消或旧响应不会覆盖新选择；手机宽度下主要按钮和概念卡可操作。创作界面保持简洁，舞台效果优先给游客端。

### 4.4 第四步：媒体与声音增强（P1，可并行）

先做能立即提升效果的项目：每样板 3–5 段预生成旁白，打磨开场、分支反馈和结尾。继续使用现有图片；需要更强主视觉时补重点画面，不要求每幕重做。

新增媒体采用简单 manifest 登记路径、类型、大小、哈希和用途，目的是可靠加载、导出和复现，不扩展为许可审核平台。生成图下载到项目受控目录或持久化资产存储，避免把临时 URL 直接写入最终包。接现有媒体收集/压缩/引用替换逻辑，不另建打包器。

Tavily、Seedream、TTS 适配按可用账号推进；服务端保存凭据，供应商失败仍可用预取资料与现有成品。是否启用计费调用由团队现有账号/预算安排决定，不应阻塞无需供应商的其他任务。

当前离线只保证两份固定样板。新 Agent 草稿可先在线预览、导出，不把“任意生成故事一键完整离线”列为这轮 P0；若更新固定样板，再重新 build 并跑离线回归。

## 6. 推荐推进节奏与提交切片

以下是开发顺序，不是已经验证的工时承诺；按剩余比赛时间压缩。

1. **切片 1：契约和 fixture**——共享类型、校验、两景点输入、候选示例；A 先交付，B/C 即可接手。
2. **切片 2：独立草稿导入**——采纳到编辑、预览与打包；尽早证明新链能接回旧系统。
3. **切片 3：真实模型概念**——两个概念可选，保存阶段产物。
4. **切片 4：节拍与编译**——完整候选进入播放器，两景点逐一跑通。
5. **切片 5：Studio 接线**——串联进度、选择、失败保留与采用。
6. **切片 6：演示收口**——旁白、节奏、手机试玩、五分钟讲稿、成功产物备用包。

每个切片保持可构建，独立提交、及时推送；PR 描述写明变化、实际验证和剩余问题。先把当前双样板基线整理进团队认可的集成分支，再从同一基线开任务分支；不要让多位成员直接向同一个功能分支并发推送。无需为这次文档交接立即合并 main。

**时间不足时保留：**两个现有样板 + 两概念可选 + 至少一份真实模型编译并采纳的故事 + 清晰的演示路径。优先砍掉自动检索、自动生图、复杂 Job 管理、多 Critic 与导航，而不是砍掉故事效果。

## 8. 环境、命令与验证方式

Node.js 24；应用在 `tour-hub-web`。已有 checkout 先拉取正确分支，再按本地环境安装依赖。

```bash
git fetch origin feature/timewalker-dual-samples
git switch feature/timewalker-dual-samples
git pull --ff-only origin feature/timewalker-dual-samples
cd tour-hub-web
npm ci
npm run dev:full
```

Vite 端口 5174，API 8787，生产 preview 默认 4173。不要为修复本地网络而重写整个锁文件。锁文件含企业镜像地址；云端曾使用工作区外置依赖副本替换下载镜像，本地按可访问的镜像处理即可。更完整的环境迁移说明见 09。

真实模型变量放在应用目录 `.env.server.local`，不提交。地图不是故事主线依赖；天文馆不需要高德。数据包、浏览器草稿与运行中的服务是三回事，Git 不会同步 localStorage 中的成果。

```bash
npm test
npm run lint
npm run build
npm run test:builder
npm run test:creator
npm run test:dual
```

浏览器脚本需要 Playwright 和 Chromium；云端可用以下变量，本地使用自己的安装路径或默认 Playwright：

```bash
TIMEWALKER_PLAYWRIGHT_MODULE=/opt/codex/cua_node/lib/node_modules/playwright/index.mjs \
TIMEWALKER_CHROMIUM=/usr/bin/chromium npm run test:dual
```

`test:smoke`、`test:builder`、`test:playability`、`test:creator`、`test:dual` 需要开发服务；`test:offline` 必须在最新 build 后运行，会启动独立测试服务器。代码变更按影响范围跑相关套件，集成收口再跑全部六套；纯文档变更无需重跑应用测试。

新 Agent 必须增加有价值的验证：非法输出不成为候选、分支可终止、旧包不被覆盖、取消保留成果、新媒体导出后仍可加载。自动化可 mock provider 验证失败处理，但验收记录另列真实供应商运行结果，二者不能混写。

## 9. 最终演示验收与五分钟结构

最终检查：两样板能独立打开并完成；主题明显不同；选择有反馈、观察能留下个人文字；声音失败能继续；真实模型产物可导入和播放；发布后媒体可加载；无模型配置时固定样板仍能演示。素材署名、许可清单不进入这份验收。

建议五分钟：

### 2026-10-15｜切片 1：Agent 共享契约与候选校验

- 玩家经历的节拍限定为 4–6 个，分支展开后的场景可多于节拍；候选必须完整映射每个 V1 场景，并保持地点、分支合流和所选概念一致。

### 2026-10-15｜切片 3：真实模型双概念服务

已新增 `POST /api/agent/concepts`，复用现有网关的 DeepSeek 配置、Origin 限制、限流、并发上限、超时/取消和错误脱敏，不增加浏览器密钥或另一套模型配置。

- 请求严格使用共享 `CreativeBrief`，并从当前已发布包构造有上限的地点、摘要、来源和媒体上下文；输入内容在系统提示中明确作为不可信数据处理。
- 模型必须返回严格包装的两个 `StoryConcept`。除 ID 不重复外，命题、悬念、地点作用和结尾回收均必须不同；只改标题或返回额外字段会以 `GENERATION_INVALID` 拒绝。
- 成功响应包含概念、请求 ID、实际配置的模型名、`concepts` 阶段、整数耗时，以及当前基础包的 ID、发布时间版本和内容指纹，供后续编译与采纳绑定。
- 未配置模型继续返回 `MODEL_NOT_CONFIGURED`，供应商地址、错误和凭据不进入响应；本地模板及其他旧网关接口保持可用。

### 2026-10-15｜切片 4：节拍与 V1 候选编译

已新增 `POST /api/agent/compile`，接收严格的 brief、双概念阶段返回的基础包身份和用户所选概念；版本或指纹失效会在调用模型前返回 `STALE_BINDING`。

- 服务端使用当前包的 motif 模板建立合法 V1 骨架，模型在现有地点、媒体、来源、场景图和白名单动作内生成 4–6 个玩家节拍并改写叙事，presentation 必须逐字段保持基础包设置。
- 服务端组装完整 `AgentCandidate` 后统一经过节拍映射、地点、媒体、来源、V1 图与可玩性校验；heritage 和 cosmos 成功路径均已覆盖，并验证结果可直接传给 `createAgentDraft`。
- 首次 JSON 或候选校验失败时，只进行一次携带脱敏、截断诊断的定向修复；第二次失败返回 422。自动化明确验证不会发生第三次模型调用。
