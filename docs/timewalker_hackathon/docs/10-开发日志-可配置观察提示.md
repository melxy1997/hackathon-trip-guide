## 逻辑单元 1：观察提示契约与 Builder 产物

### 实现

- `photo_or_tap` 新增可选 `prompt` 和 `hints`，旧包省略字段时行为不变。
- 主提示必须是 1–240 字非空文本；轻提示最多 3 条，每条必须是 1–80 字非空文本。
- 本地模板的自然与匠心分支生成不同主提示和轻提示，继续明确自由观察、无标准答案。
- 在线模型起稿提示词只允许在既有结构中改写受限提示字段，继续禁止宣称照片已被识别。
- schema 与 Builder 单元测试覆盖合法边界、错误类型、旧包兼容和双分支差异。

### 验收

- `npm test`：59 项通过，0 失败、0 跳过。

## 逻辑单元 2：游客端提示展示

### 实现

- 播放器把当前 `photo_or_tap` 的主提示和轻提示传入观察卡，不从其他场景或分支推断内容。
- 有主提示时替换原有通用帮助文案；旧包没有主提示时保留原文。
- 有轻提示时显示原生 `details/summary` 折叠区，默认收起并由游客按需展开；没有轻提示时不渲染空入口。
- 提示位于照片之前的普通文档流中，不覆盖照片、记录输入或底部确认按钮；折叠入口保持 44px 最小触控高度。
