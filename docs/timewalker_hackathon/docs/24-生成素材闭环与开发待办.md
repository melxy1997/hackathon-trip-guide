## 切片一：生图后端与持久素材

新增 `POST /api/agent/media`：`{ candidate, sceneId, artDirection?, confirmBilling:true }`。先校验当前候选和基础包，只替换指定章节的第一个图片块；其他章节、原候选及种子包不变。结果返回新候选、artifact、素材与耗时；仍需用户采用到独立草稿。

配置：服务端 `ARK_API_KEY`、`ARK_IMAGE_MODEL`，可选 `ARK_BASE_URL`（默认火山方舟 `/api/v3`）。每次最多生成一张 1440×2560 竖版图片，保持水印；一次并发，不自动重试计费调用；每候选最多六份新增资源。请求必须显式确认生图调用。无配置时明确报错，现有图片仍可用。当前环境没有这些凭据，本轮未发生真实生图调用。

图片立即下载到应用 `.agent-jobs/assets/`；可通过 `AGENT_ARTIFACT_DIR` 指定持久目录。按内容 SHA-256 命名，写文件再写元数据和请求缓存，临时文件 rename 提交。模型、提示词、尺寸、Provider 地址组成缓存键；相同请求重启后可复用，不再次调用计费服务。已生成文件不会因浏览器取消而主动清理。进程重启不代表正在运行的生图任务能恢复。

图片以 `/api/agent/assets/<hash>.<ext>` 访问；候选只存小型受控引用。API 根据本地元数据、长度、文件签名和哈希校验图片。生成服务的临时 URL 不写入候选或元数据，供应商 Authorization 不转发到 CDN。下载仅接受支持的 HTTPS 火山/字节图片域名，不跟随重定向；默认单图最多 5 MiB。新 URL 域名如超出适配器范围，需要后续明确扩展，不能静默跳过失败。

实现入口：`server/agent/imageProvider.ts`、`assetStore.ts`、`media.ts`、`gateway.ts`；新增自动化覆盖实际网关替图、候选校验、重启读取/缓存、损坏检测、媒体类型/大小、凭据隔离、缺配置与错误脱敏。验证使用测试图片与替身 Provider，不计为真实 Seedream 成功。

## 切片二：Studio 分幕配图与携带新增媒体

入口：`/publish` 的 Creative Studio → 编译候选后 → 「为故事补一张关键画面」。选择章节、补充画面要求、确认本次服务调用，再点击「为本章生成插画」。自动采用原包的 heritage/cosmos 视觉方向和当前章节叙事，界面展示真实返回的新图或缓存复用提示。

每次点击后清除调用确认；章节、画面要求或候选变化后也需重新确认。等待期间禁止重复提交，可在配图区域停止等待。失败保留原图与候选；计费服务已开始时取消等待不保证撤销费用。素材地址不可用时显示文字回退，不让页面崩溃。

候选自动保存仍使用小型 API 素材引用，避免本机 localStorage 塞满；素材本身落在服务器持久目录，重启后可继续读。**迁移服务器需备份 `.agent-jobs/assets`，或先导出成果文件。**代码推到 GitHub 不代表生成图文件也已同步。

「导出创作成果」现在读取全部新增图片/音频并嵌入导出副本，复用已有发布媒体的压缩编码逻辑。大于 2 MB 的图片可在浏览器压缩为长边不超过 1600 的 WebP；不改原始文件、不改正在编辑的候选。每项继续遵守既有安全引用上限，文件总上限仍为 8 MiB。失败不下载半成品文件。基底样板素材仍依赖同版本仓库包，不重复嵌入全部底图。

导入成果后新增素材不依赖原机器 `/api/agent/assets`；采用成独立草稿，再用原审核/发布链真正打入 `assets`。服务端 artifact 哈希记录的是生图后服务端候选版本；导出压缩是副本变换，不把它误作整个导出文件的哈希。

媒体请求单独允许最多 8 MiB JSON，以支持导入过内嵌图片的候选再次配图；其余模型接口仍保持原 64 KB 限制。后端生成新候选后继续执行 `assertAgentCandidate`，不会借此放宽旧 Builder。

实现入口：`CandidateMediaPanel.tsx`、`CreativeStudio.tsx`、`agent/portable.ts`、`draftStore.ts` 的共享 `materializeMediaReference`。新增 portable 测试验证图片/音频内嵌、别名替换、失败保留原始候选。Studio Chromium 已验证：调用确认、缺配置、生成成功/缓存、实际显示图片、导出文件内嵌、新环境原素材接口不可用时仍可导入、采用后实际调用发布打包函数，最终包媒体无 Agent API 依赖。测试服务均为明确标记的 fixture，不计为真实 Provider 成功。

下一位可直接接以下任务：

1. **真实作品彩排（当前最高优先级）**：配置模型/搜索凭据，执行 `npm run agent:rehearse`；导入一份真实候选，在 Studio 用实际可用的 Seedream 模型给一章配图。导出文件后换浏览器导入，采用→预览→发布，保留真实请求与成果。缺乏凭据不是继续堆模拟成功的理由。
2. **声音效果**：先给两个成品样板各补 3–5 段预生成中文 MP3，用已有 audio 块与浏览器朗读回退。若要自动生成，单独实现 TTS Provider 与音频 AssetStore；本轮 AssetStore 仅支持图片，不能把 MP3 直接塞进图片接口。
3. **更自由的故事编译**：当前模型仍参考固定蓝图产出 V1。可新增更明确的中间剧本/节拍结构，再由确定性 TypeScript 编译成场景和动作，减少模型填写底层 JSON 的负担；保持旧接口和候选导入兼容，不要求一次重写播放器。
4. **自主 Agent**：先验证真实模型 tool_calls 往返，再将已可运行的研究、生图服务封装成受限工具接 Deep Agents。不要因为参考方案有多个角色就先建复杂管理面板，也不要默认把付费生图暴露成可无限调用的工具。
5. **现场体验收口**：两包节奏、开场/终幕、真机声音和下载分享；有余力再做局部改稿与持久 Job。HTTP 取消与服务端文件持久性是两回事，不能把素材缓存称为任务恢复。

迁移清单：拉取本功能分支、安装既有锁定依赖、配置服务端环境、复制/挂载生成素材目录或导入携带媒体的成果文件。生成服务所需的模型 ID 必须来自团队账号；当前环境没有真实供应商配置，因此本轮交付的是已验证的接入和闭环，不宣称已产出真实 Seedream 图片。
